# 手机确认、图片与文件（0.3.0）

目标：Codex、WorkBuddy、豆包、DeepSeek Harness 的任务在等待用户操作或返回非文本内容时，手机有可用的处理入口。默认仍为 CLI 优先，仅在可证明尚未执行任务的启动失败时转桌面；明确选择桌面则跳过 CLI。

## 手机上如何使用

- 聊天中出现确认卡片时，核对请求和选项再点击。Codex 的补充信息请求可直接填写回答。确认没有默认选中或自动提交。
- WorkBuddy / DSH 的桌面问题卡片会同步实际控件。选择选项后，如果电脑仍要求“提交”，手机会更新下一步按钮。
- 复杂弹窗、输入框、图片操作：点击当前回复的“查看电脑与操作”。可刷新当前 Agent 窗口，选择实际控件、填入文字；需要点击无名称的图标时，先打开“启用画面点击”，再点选对应位置。缩放或拖动图片不会直接点击电脑。
- 本地文件链接和协议返回的图片显示为附件，点击后核对路径并读取。图片可预览；文件通过 Android 系统文件选择器保存，保存后可用其他应用打开。每个文件最大 20MB。
- 桌面图片无法提取原始 URL 时，显示明确标注的“电脑画面（非原图）”。可用电脑画面的保存/下载控件将原图保存到电脑，再使用“从电脑下载文件夹取回原文件”。列表只展示下载目录最近 30 个普通文件，不自动选择或读取文件。
- 对于 WorkBuddy / DSH 把链接显示成按钮的回复，可使用“提取回复中的文件链接”。适配器只复制匹配当前任务的已完成回复，核对可见文字并恢复原剪贴板。

## 接入范围

| Agent | 默认后台接入 | 直接桌面接入（macOS） |
|---|---|---|
| Codex | `app-server` stdio：命令/文件审批、用户提问、图片与文件链接 | 当前应用窗口、实际确认控件、文字输入、截图与文件 |
| WorkBuddy / CodeBuddy | ACP v1 stdio：单次权限选择、消息/工具图片与文件链接；未登录时启动失败转桌面 | 原生问题卡片、实际控件与窗口画面、复制原始回复链接 |
| DeepSeek Harness | ACP v1 stdio：权限选择及结构化内容；独立 CLI 凭据缺失时转桌面 | 原生提问卡片、选项与提交、实际控件、回复附件 |
| 豆包 | 使用已安装桌面 APP | 对话追问、确认控件、图片画面、电脑保存/下载与原文件取回 |

ACP 本身不保证包含每个产品的私有交互。DSH 的 ACP 明确不提供其专有 elicitation 卡片，完整桌面提问体验请选“直接使用桌面应用”。CLI 任务已经开始后，不会为了某个不支持的交互自动重发到桌面。

Windows 既有聊天路径保留；本轮新加的桌面截图、控件转发只实现并验收 macOS。Windows ACP/app-server 依赖对应版本支持；Windows 桌面交互不在本轮实机验收范围内。

## 状态和权限

- 确认 token 只保存在运行时，单次使用，3 分钟过期；任务结束、取消、重新连接后不可重用。历史聊天不恢复可执行按钮。
- 电脑画面操作 token 单次使用，60 秒有效。执行前再次核对应用进程、当前对话、问题文字、控件和窗口位置。实时计时文字不参与比对。界面变化后要求刷新，不自动重试点击。
- 支持 app-server 已解析的审批与问题类型、ACP 单次权限请求；未知协议方法会明确拒绝，不猜测批准格式或转发任意 RPC。
- macOS 需要解锁及辅助功能授权；截图额外需要当前 SSH/osascript 会话的屏幕录制授权。系统权限、登录、验证码、不能访问的安全输入框仍需在电脑处理。不会自动授予系统权限。
- 原始回复使用纯文本渲染；附件不执行 HTML。文件通过固定 SSH 主机指纹保护的 SFTP 读取，不把远程路径拼进 shell 命令。
- APK 保持原签名，可覆盖安装。新功能不需要新增常驻 Mac APP。

# 电脑持久任务服务与 OpenMuse 复用

本次保留 Java + WebView Android 架构。OpenMuse 的 React Native ChatScreen 依赖 CopilotKit、会话与任务上下文、浏览器和后端状态，换成 RN 还需迁移 SSH、加密凭据、文件选择/保存、原生确认与生命周期处理。对当前 Android 交付，移植交互成本更低。未来若同时支持 iOS，可再独立评估 RN。

| 方案 | 当前复用收益 | 需要新增的工作 | 当前选择 |
| --- | --- | --- | --- |
| Java + WebView 移植交互 | 保留现有原生链路，复用队列/输入/消息交互 | Web UI 适配、服务状态接入 | 采用 |
| RN + OpenMuse | 可使用其 RN 组件结构 | 原生桥迁移、CopilotKit/上下文适配、全量移动回归 | 暂不迁移 |

## 连接

电脑需 Java 17 或更新版本、SSH 以及已安装登录的 Agent。连接设置开启“电脑持久任务服务”；自动探测失败时，在高级设置填写电脑 Java 可执行文件绝对路径。APK 将版本化服务 JAR 上传到 `~/.agent-control/runtime/`，通过 SSH 启动独立 JVM，不新增任务服务监听端口。既有直接 SSH 模式可继续使用。

请求经 SFTP 写入私有文件，服务在执行前落盘，使用文件锁保持单实例。结果存储于 `~/.agent-control/data/`，重连轮询恢复。同请求 ID 内容不同会拒绝；重复请求不会重复执行。相同会话按顺序执行，全服务最多三个任务同时运行，桌面应用操作共享互斥锁。

## 恢复与操作

- 退出手机或断开 SSH，已提交任务继续在电脑执行。手机重连取得结果，不重新提交。
- 服务重启时，原正在执行或等待确认的任务标成“状态待确认”，原审批失效，绝不自动重放；未开始的队列可继续执行。
- 暂停/继续针对未开始任务。停止运行中的任务不能证明所有远端进程已退出，因此显示状态待确认。
- 审批仍是一次性并有时效；不自动批准历史确认。
- 回复附件尽量归档原始字节到私有 files 目录；无法归档的原路径附件依赖原文件仍存在。
- 同会话传递最近八轮成功问答，保存原生 Agent 会话 ID 供核对，当前仍为每任务创建新的原生会话。
- 服务空闲时重连可升级运行时；有执行中任务时延后升级。
- 新建对话或切换 Agent 会先关闭旧会话的提交入口、取消排队任务并请求终止执行。电脑确认进程退出、桌面任务停止后才建立新会话；未确认时保留旧会话并显示原因，断线时须先重连。旧会话保留为只读记录，迟到提交会被电脑拒绝。
- 消息、会话和任务时间显示到秒，重连回放沿用电脑保存的原始事件时间。

记录上限 1000 个任务；手机同步最多 30 个任务且总大小受限。需在电脑归档旧记录。当前没有系统推送，网页监控变化在 APP 内展示。

## 可选浏览器

APP 的浏览器页可提交安装任务。电脑另外需要 Node.js 24 与 npm，安装 Playwright Chromium。工作进程仅监听 `127.0.0.1:8790`，使用电脑私有 token，手机经 SSH 转发操作。`~/.agent-control/browser.json` 保存私有配置，`browser-profiles/` 保存页面状态，均不要公开。

OpenMuse MIT 浏览器 worker 原源码保留，限制访问公网地址，阻止私网/本机目的地。Codex 可调用只读 `read_public_page` MCP 工具，获得实际页面文本并生成聊天内浏览器卡片；任务结束后手机可接管截图、点击、输入和按键，也可结束会话释放浏览器槽位。空闲关闭的会话在用户明确请求读画面时重新打开保存的 URL。ACP 尚未挂载此 MCP 工具。网页任务监控支持基线、变化去重与失败退避，连续五次失败自动暂停。

Windows 常驻服务通过 WMI 在 SSH 作业之外启动，避免请求通道关闭时被 OpenSSH 一并终止。RPC 标准输出明确使用 UTF-8，避免 Java 17 的 GBK 默认编码破坏中文。Windows 回归覆盖请求进程退出后保持相同服务 PID、中文与 emoji 往返；浏览器安装仍需目标环境验收。原有 Windows 直接 SSH 与桌面桥接保持原路径。
